# Project 15 - Autonomous Cloud Migration & Application Modernization Agent

A working, provider-neutral POC of an agentic platform that discovers an enterprise
application estate, assesses it, classifies every application into a 7R migration
strategy via a visible rules table, plans constraint-aware migration waves, executes
approved waves against a simulated target environment (with preflight checks, a human
approval gate, validation gates and automatic rollback), renders structured target
architectures for aws/azure/gcp profiles, and evaluates itself against machine-written
ground truth.

**Everything runs locally against a deterministic simulator. No paid cloud account,
no real AWS/Azure/GCP calls. The LLM layer defaults to a deterministic mock narrator
that only restates facts - it never decides anything.**

Verified on Python 3.11 / Windows.

## What it does (end-to-end)

1. **Seed** a deterministic estate (~120 applications by default, seeded RNG): mixed
   legacy runtimes, EOL platforms, shared services, batch jobs, SFTP transfer logs,
   CMDB records, and ONE undocumented dependency that exists only as a nightly file
   drop landing inside another application's registered mount.
2. **Discover**: correlate CMDB + network flows + scheduler extracts + transfer logs
   into `graph_edges` (9 relation types) using NetworkX for analysis. The hidden FTP
   dependency surfaces only through transfer-log correlation.
3. **Assess**: deterministic dimension scores, technical-debt index, complexity label,
   and a 9-point agentic-readiness checklist per application.
4. **Classify**: ordered first-match 7R rules table (R01..R09). The LLM never picks
   strategies; it narrates the decided facts afterwards.
5. **Plan**: waves 0-3 under topological, security-zone, criticality and concurrency
   constraints. Violating operator overrides become `BlockedMigration` records with
   reasons and suggested resolutions.
6. **Execute** (human-gated): preflight (7 checks) -> `AWAITING_APPROVAL` ->
   approve/reject -> execute -> per-app validation sequence -> placement mutation or
   automatic rollback. A planted app (`receivables-matching-service`, Oracle-only AQ
   feature) fails `database_connectivity` in wave 1 and rolls back while the rest of
   the wave completes.
7. **Evaluate** against ground truth written at seed time: discovery recall/precision,
   strategy accuracy vs 12 hand labels, exact blocked-set match, forced-rollback check.
   The deterministic world scores 100% on every axis (see EVALUATION.md).

## Quickstart (local venv)

```powershell
cd "D:\ai apps dump\claude code project\enterprise-agentic-ai-portfolio-batch-3\15-cloud-modernization-agent"

python -m venv .venv                       # once
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 1. full assessment report (seed -> agents -> report)
.venv\Scripts\python.exe scripts\generate_migration_assessment.py

# 2. wave 0/1 execution demo incl. the failing app + rollback story
.venv\Scripts\python.exe scripts\run_wave0_wave1_demo.py

# 3. serve the cockpit UI + API
.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --port 8015
# open http://127.0.0.1:8015/
```

The SPA is served at `/` (vanilla ES modules, zero CDN). The amber MOCK MODE badge in
the header comes from `GET /api/v1/meta`.

## Configuration (.env.example)

| Variable | Default | Meaning |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./data/cloud_modernization.db` | SQLite default; PostgreSQL works via e.g. `postgresql+psycopg://user:pw@host/db` |
| `LLM_MODE` | `mock` | `mock` = deterministic narrator; `openai-compatible` = any OpenAI-compatible endpoint |
| `LLM_BASE_URL` | `http://localhost:11434/v1` | used when `LLM_MODE=openai-compatible` |
| `LLM_API_KEY` | *(empty)* | optional Bearer token; never logged |
| `ESTATE_SIZE` | `120` | applications generated by the simulator |
| `CORS_ORIGINS` | `http://localhost:8015` | comma-separated allow list |

## API surface (prefix `/api/v1`)

`GET /api/v1/meta`, plus:

- `POST /simulator/seed` `{size, reset}`
- `POST /pipeline/run` - full agent run (discover, assess, classify, plan, validate)
- `GET /applications` (q, domain, runtime_id, strategy, readiness_band, criticality_min/max, sort, limit, offset), `GET /applications/{id}`, `GET /graph`
- `GET /assessments`, `GET /assessments/{id}`, `POST /assessment/run`
- `GET /strategy-rules`, `GET /strategies`, `GET /strategies/{id}`
- `GET /waves`, `GET /waves/{n}`, `POST /waves/plan`, `GET/POST /waves/{n}/preflight`
- `GET /blocked`
- `GET /approvals`, `POST /approvals/{id}/approve`, `POST /approvals/{id}/reject`
- `POST /waves/{n}/execute`, `GET /executions`, `GET /validations` (requires filter)
- `GET /target-architectures`, `GET /target-architecture/{id}?provider=aws|azure|gcp&format=json|yaml`
- `GET /opportunities`, `GET /risks`, `GET /audit/actions|tool-calls|events`, `GET /metrics-summary`
- `POST /evaluation/run`, `GET /evaluation/latest`
- Ops: `/health`, `/readiness`, `/metrics` (Prometheus)

Validation failures return 422, illegal workflow transitions/gates return 409,
missing rows 404. Errors never echo secrets or stack traces to clients.
